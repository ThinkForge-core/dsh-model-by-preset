# dsh-model-by-preset

Клиентский (браузерный) плагин для **web**-профиля **DeepSeek Harness**, который
привязывает модель сессии к её **пресету агента** — чтобы модель, выбранная в
одном пресете, больше не «протекала» во все новые сессии.

[English version](README.md)

## Что делает

Когда вы создаёте **новую (пустую)** сессию, DeepSeek Harness открывает её на
*последней использованной* модели (глобальный `agent-default-model`). Если вы
переключаетесь между пресетами, каждому из которых нужна своя модель (локальная
Ollama — для одного, облачная DeepSeek — для другого, vision-модель — для
третьего), приходится каждый раз вручную выбирать модель.

`dsh-model-by-preset` убирает это трение: вы один раз настраиваете, с какой
моделью и уровнем размышления должна открываться новая сессия **для каждого
пресета агента**. Новая сессия на таком пресете автоматически переключается на
заданную модель через тот же RPC `session.selectModel`, что и пикер модели в UI.

- Авто-маппинг применяется **только к новым пустым сессиям**. Сессия с историей
  не изменяется никогда — ручной выбор всегда в приоритете.
- Пресеты, которые вы не настроили, остаются на **глобальной модели по умолчанию**
  (без переопределения).
- Строка-фолбэк `*` задаёт модель для **любого другого / будущего пресета**.

## Почему клиентский плагин (а не host-плагин)

В текущем харнессе модель сессии резолвится лениво, на каждый запрос. Агент без
явного выбора использует глобальный `agent-default-model`, а явный выбор хранится
в per-agent сторе выбора, которым владеет api-proxy. Поддерживаемый способ сменить
модель сессии — RPC `session.selectModel`, ровно тот, что вызывает браузерный
пикер модели и что отправляет этот плагин.

`selectModel` также сохраняет выбор как глобальный дефолт («последняя выбранная
модель = новый дефолт»). Этот побочный эффект намеренно **не трогается** — именно
он держит плашку/чип модели честными. Поскольку плагин сопоставляет модель для
*каждого* пресета, сохранённый дефолт просто отслеживает тот пресет, которым вы
пользовались последним.

## Как срабатывает

Прокинутые фреймы `session/event` уходят в per-session контроллеры, а не в корневой
контекст, поэтому `ctx.on("session/event")` у корневого плагина не срабатывает.
Вместо этого плагин подписывается на **клиентский стор списка сессий**
(`ctx.sessions.list`, snapshot-стор, обновляется на `session.create` / смене
пресета). Каждая строка несёт `agentPreset` и `blank`. Строка авто-маппится только
когда:

- `blank === true` (нет истории — использованные сессии никогда не откатываются), и
- записан `agentPreset` (значит, известна цель применения), и
- у этого пресета есть переопределение, чья модель отличается от текущей модели
  сессии.

## Требования

- **web**-профиль DeepSeek Harness (DSH `0.1.1-rc.2` или новее).
- Провайдер(ы) и модель(и), которые вы хотите назначать, должны быть уже настроены
  в вашем харнессе (settings / providers). Плагин только *выбирает* модель — он не
  создаёт провайдеров.
- Node.js с CLI `dsh` в `PATH`.

## Установка

### Вариант 0 — автоматический кроссплатформенный инсталлятор (рекомендуется)

Инсталлятор на **Python 3** без сторонних зависимостей (`install.py`) сам
обнаруживает раскладку DSH (`DSH_HOME` / `~/.dsh`, профили), проверяет
инструментарий (`dsh`, `pnpm`, `npm`) и предлагает выбрать способ установки.
Работает на Linux, macOS и Windows и покрывает все варианты ниже, включая
деинсталляцию.

```bash
cd /путь/к/dsh-model-by-preset
python3 install.py            # интерактивное меню
python3 install.py --list     # просто показать, что он обнаружил
python3 install.py --method A # dev-symlink в профиль по умолчанию (web)
python3 install.py --method B --profile web
python3 install.py --method C            # GitHub-установка; owner из git remote
python3 install.py --method U --yes              # деинсталляция без запросов
python3 install.py --dry-run  # показать команды, не выполняя их
```

Полный CLI описан в docstring в начале `install.py`.

### Вариант A — из исходников (dev-symlink)

```bash
cd /путь/к/dsh-model-by-preset
dsh plugin --profile web add .
```

Это создаёт симлинк из репо в ваш профиль, поэтому правки подхватываются:

- изменение `client.js` → достаточно **жёсткого обновления браузера**
  (Ctrl/Cmd+Shift+R);
- изменение `lib/index.js` → нужен **перезапуск `dsh web`**.

### Вариант B — из собранного тарбола

```bash
cd /путь/к/dsh-model-by-preset
npm pack                      # -> dsh-model-by-preset-0.1.0.tgz
dsh plugin --profile web remove dsh-model-by-preset   # только если уже установлен
dsh plugin --profile web add file:/абс/путь/dsh-model-by-preset-0.1.0.tgz
```

Затем перезапустите `dsh web`. Имя файла должно совпадать с версией в
`package.json`.

### Вариант C — из GitHub (публичный релиз)

```bash
dsh plugin --profile web add <owner>/dsh-model-by-preset
```

`dsh plugin` — тонкий форвардер на pnpm, который трактует `<owner>/<repo>` как
GitHub-зависимость: клонирует опубликованный репозиторий с `github.com` и ставит
его как пакет плагина. Репозиторий должен быть запушен на GitHub. Тот же самый
способ делает `install.py --method C`, беря owner либо из `--owner`, либо из
`origin` git-remote этого чекаута (`git remote get-url origin`); никакого
захардкоженного owner по умолчанию нет.

## Использование

1. Откройте редактор slash-командой:

   ```
   /model-by-preset
   ```

2. Для каждого пресета (живой список из вашего реального ростера — встроенные и
   локально созданные пресеты) задайте модель:
   - **выпадающий список моделей показывает то, что реально рекламируют ваши
     настроенные провайдеры** (берётся на лету из host-каталога `llm.models`,
     сгруппировано по провайдеру — никакого захардкоженного списка моделей), и
   - выберите **уровень размышления**: выпадающий список предлагает собственные
     уровни модели (`reasoning.efforts`), когда они есть в каталоге, а иначе —
     известные уровни семейства провайдера (DeepSeek и др.: `off | low | high |
     max`; Ollama: `off | on` для `think`). Последний пункт — **«type custom…»** —
     открывает поле свободного ввода для любого другого значения, которое
     принимает ваш провайдер (например `medium`); оно сохраняется как есть.
   - Оставьте модель на **«(follow global default)»** для отсутствия
     переопределения.
   - `*` = любой другой / новый пресет.

3. Нажмите **Save**. Сопоставление хранится в localStorage
   (`dsh-model-by-preset.overrides`, ключ `"preset"` → `"provider/model[/effort]"`,
   `"*"` = фолбэк; флаг дебага `dsh-model-by-preset.debug`).

4. Создайте **новую** сессию на пресете — плашка модели должна автоматически
   показать заданную модель/effort для этого пресета.

Сохранение применяет новое сопоставление **немедленно** — для изменения настроек
не нужны ни перезапуск приложения, ни перезагрузка браузера. (Только правки
собственного `client.js` плагина требуют жёсткого обновления страницы, а правки
`lib/index.js` — перезапуска `dsh web`; изменение маппинга в редакторе не требует
ни того, ни другого.)

## Файлы

- `client.js` — браузерная половина (формат `__ModuleLoader__`, написана вручную,
  без бандлера): вся фича (авто-маппинг + окно редактора `/model-by-preset`).
- `lib/index.js` — host-половина: регистрирует опциональный debug-приёмник
  `/api-ext/dsh-model-by-preset.debug` (пишет
  `$DSH_HOME/dsh-model-by-preset-debug.logl`; используется только когда включён
  тумблер дебага в редакторе) и хелпер очистки
  `/api-ext/dsh-model-by-preset.debug-clear` (удаляет этот файл — у редактора есть
  кнопка «Clear debug log» рядом с тумблером дебага).
- `cordis.patch.yml` — вставляет строку плагина в композицию профиля.
- `package.json` — манифест (`dsh.client.web` + inject client-runtime/connection).
- `install.py` — кроссплатформенный Python-инсталлятор (инструмент репозитория;
  в тарбол пакета не входит).

## Проверка

1. жёстко обновите страницу;
2. введите `/model-by-preset` → откроется редактор: выберите модель + effort
   размышления для каждого пресета, при необходимости включите дебаг, Save;
3. создайте НОВУЮ сессию на пресете; плашка модели должна показать заданную
   модель/effort для этого пресета (после Save перезапуск не нужен);
4. если не сработало — включите тумблер дебага в редакторе и посмотрите
   `~/.dsh/dsh-model-by-preset-debug.logl` (клиент пишет туда события
   `scan`/`select`); кнопка «Clear debug log» в редакторе удаляет файл.
